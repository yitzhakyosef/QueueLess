# QueueLess - מספרת רמת גן

מערכת דמו לקביעת תורים במספרה, שנועדה למנוע בלאגן בתורים, כפילויות, שיחות טלפון מיותרות וניהול ידני ב-WhatsApp.

המערכת היא MVP לקורס Vibe Coding: פשוטה, עובדת, בעברית, RTL, עם חוויית משתמש שנראית כמו אתר אמיתי של מספרה.

## אתר חי

- דומיין הפרויקט: `https://queue-less-rho.vercel.app/`
- קישור להצגה: `https://queue-less-rho.vercel.app/QueueLess.html`

## מה המערכת יודעת לעשות

- לקוח נרשם ומתחבר בצורה מסודרת.
- OTP מופיע גם בהרשמה וגם בהתחברות.
- לקוח קובע תור עם שירות, תאריך, שעה ונייד כשדות חובה.
- לקוח רואה את “התורים שלי” ואת סטטוס התור שלו.
- שעה ננעלת מיד אחרי שליחת בקשה, גם כשהסטטוס עדיין `pending`.
- ביטול תור משחרר את השעה בחזרה.
- ביטול על ידי בעל העסק מוצג ללקוח כסטטוס “בוטל”, כולל רענון תצוגה דרך אירוע `storage` בטאב פתוח אחר.
- בעל העסק מאשר ומבטל תורים.
- בעל העסק חוסם ימים שלמים או טווח שעות בתוך יום.
- חסימה שמתנגשת עם תורים פעילים מציגה אזהרה ומבטלת אותם רק אחרי אישור בעל העסק.
- בעל העסק רואה רשימת לקוחות, כמות תורים וחיפוש לפי שם או נייד.
- נתונים נשמרים ב-`localStorage` ושורדים רענון.

## תסריט דמו מומלץ לכיתה

1. פותחים את `QueueLess.html` או את הקישור הישיר באתר החי ומסבירים שהמערכת פותרת בלאגן בתורים במספרה.
2. נרשמים כלקוח ראשון, למשל “ישראל ישראלי”, נייד `0501111111`, ת.ז `123456789`, סיסמה `2468`.
3. מזינים OTP שגוי ומראים שההרשמה לא הושלמה, ואז מזינים `123456`.
4. קובעים תור לשעה `09:00` ומראים שהוא נכנס כ-`pending`.
5. מתנתקים ונרשמים כלקוח שני, למשל “דוד כהן”, נייד `0502222222`, ת.ז `987654321`, סיסמה `1357`.
6. מראים שהשעה `09:00` כבר נעולה למרות שהתור עדיין ממתין.
7. מתחברים כבעל עסק עם `RG2026`, מבטלים תור ומראים אצל הלקוח שהוא נשאר ברשימה כ-“בוטל”.
8. נכנסים לטאב “לקוחות” ומראים רשימת לקוחות וחיפוש לפי שם או נייד.
9. פותחים את טאב “חסימת תאריכים”, חוסמים טווח שעות ומראים שרק השעות האלה נעלמות.
10. חוסמים טווח שיש בו תור פעיל ומראים את האזהרה לפני ביטול אוטומטי.
11. מסבירים שכל זה נעשה בלי DB חיצוני כדי לצמצם נקודות כשל בקורס.
